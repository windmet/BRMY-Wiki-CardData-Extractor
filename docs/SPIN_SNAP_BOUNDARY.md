# Spin/Snap 数据边界

## 本仓库负责

- 从 masterdata 读取 Spin/Snap 的角色、卡面、服装、活动、发布时间和资源编号。
- 生成缺失、重复、未映射和新增机制统计。
- 为人工截图整理提供检索表和进度清单。
- 输出稳定的 JSON/CSV 数据契约，供其他工具选择性消费。

## 本仓库不负责

- Unity/Spine 资源提取、重建、渲染或动画播放。
- 桌宠运行时和交互逻辑。
- 判断本地复刻画面是否等同于游戏内最终表现。
- 用资源复刻结果替代 Wiki 组要求的游戏截图。

## Wiki 验收口径

Spin 相片页面的终稿图片以游戏内实际截图为准。Masterdata 可以证明归属关系和统计完整度，但不能证明渲染视觉与游戏客户端一致。

如果 Spine 工具输出角色/服装映射，应标记为研究或辅助证据；最终图片仍按 Wiki 组的截图规则验收。

## 与 Spine 仓库的接口

两个仓库不建立源码依赖。允许交换的内容仅限可版本化的数据文件，例如：

```json
{
  "resource_id": "09_0081",
  "character_id": 9,
  "card_id": 108,
  "costume_id": 95,
  "event_id": 7,
  "source_tables": ["mst_costume_mini", "mst_character_card"]
}
```

字段契约稳定后再单独版本化；在此之前，两个工具可以分别读取用户提供的 masterdata。
